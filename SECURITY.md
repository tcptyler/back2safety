# Security Policy

back2safety is a security tool, so we take vulnerabilities in it seriously. Thank you for helping keep its users safe.

## Supported versions

back2safety is in early development. Only the latest code on the `main` branch is supported.

## Reporting a vulnerability

**Do not open a public issue, discussion, or pull request for security vulnerabilities.**

Report privately through GitHub:

1. Go to the **Security** tab of this repository.
2. Click **Report a vulnerability**.
3. Fill in the form.

Please include:

- What the vulnerability is and where it is (file, function, or feature).
- Steps to reproduce it, or a proof of concept.
- What an attacker could do with it.
- Any suggested fix, if you have one.

## What to expect

- We aim to acknowledge your report within **7 days**.
- We will keep you updated as we investigate and fix it.
- Once a fix is released, we will credit you in the advisory unless you prefer to stay anonymous.

Please give us reasonable time to fix the issue before disclosing it publicly.

## What counts as a security issue

**In scope** (report privately):

- Vulnerabilities in back2safety's code, such as code execution, data leaks, or ways a crafted email could compromise the user's computer.
- Ways back2safety could leak a user's email content, attachments, or API keys.

**Not a security issue** (open a normal issue instead):

- An email that back2safety rated incorrectly. Open a normal issue with a redacted sample. If you believe the miss is being actively exploited at scale, report it privately instead.

## Good-faith research

We will not pursue legal action against researchers who act in good faith and follow this policy: report privately, avoid harming users or their data, and do not test against systems or accounts you do not own.
